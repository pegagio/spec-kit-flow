# Artifact flow-back and convergence

After task generation, read-only analysis compares the specification, plan, and tasks before presenting a disposition. A clean report stops at a separate implementation handoff. Routine specification findings update the specification, then require replanning, retasking, and reanalysis; plan findings require retasking and reanalysis; task findings require reanalysis. (S010)

Routine remediation stays inside the operator-issued controller scope. Constitutional, authority, material-scope, ambiguous-recovery, blocked, or invalid outcomes stop for a separate decision. A remediation command succeeding does not establish a clean analysis result. (S010)

Implementation begins only for eligible tasks after clean analysis, within the operator's selected agent and task scope. The result is reviewed as execution evidence. Discoveries may return to specification, plan, tasks, or analysis for the same feature, with dependent-artifact reconciliation and analysis required before work resumes; blockers and invalid choices stop without expanding scope. (S011)

Convergence compares implemented work with the current specification, plan, and tasks. A clean result stops for separate closeout review; bounded gaps become remediation tasks that pass analysis before another operator-invoked implementation and later convergence run. A changed artifact or implementation can make an earlier clean result stale. (S012)

Before merge, the specification, plan, tasks, and implementation form one mutable review set; accepted discoveries flow through affected artifacts before work proceeds from a changed direction. Merge freezes that feature's historical meaning, so later behavioral changes need a new feature directory. The operator invokes consistency checks; agents flag skipped checks and unresolved divergence without launching the checks independently. (S017)
